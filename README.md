# Detection of AI-Generated Scientific Abstracts Using Linguistic Features and Machine Learning

## Project Overview

This project investigates the classification of scientific abstracts into three categories:

- **Human:** Original abstracts collected from scientific journal articles and treated as presumed human-written samples.
- **GPT-3.5:** Synthetic academic abstracts generated by GPT-3.5 using article titles as input.
- **Paraphrase:** Rewritten versions of original abstracts generated by GPT-3.5.

The project explores the use of natural language processing (NLP) and machine learning to distinguish between original scientific abstracts, AI-generated text, and AI-paraphrased text.

The research workflow includes automated data collection, article metadata extraction, synthetic text generation, abstract paraphrasing, and dataset preparation. The modeling and evaluation stages will be documented after the corresponding code and experimental results are verified.

## Project Workflow

The current documented workflow consists of the following stages:

1. Collect scientific article URLs from IEEE Xplore.
2. Extract article metadata and abstracts from individual article pages.
3. Generate synthetic academic abstracts from article titles using GPT-3.5.
4. Generate paraphrased versions of original abstracts using GPT-3.5.
5. Prepare the labeled dataset for subsequent NLP and machine learning experiments.

## 1. Data Collection

### Data Source

The initial dataset was collected from scientific journal articles indexed by IEEE Xplore.

The search URLs were configured manually for different research topics and publication filters.

### Search Configuration

- **Source:** IEEE Xplore
- **Content type:** Journals
- **Publication period:** 2020–2022
- **Research topics:** Approximately 100 manually specified topics
- **Example search topic:** Power Engineering
- **Maximum pages per execution:** 10
- **Output format:** Excel (`.xlsx`)

The initial data collection process resulted in approximately 8,106 records. This count refers to the reported collection stage and does not necessarily represent the number of unique, complete, or successfully processed abstracts in the final dataset.

### Link Collection Workflow

A Python script was developed using Selenium and pandas to collect article URLs from IEEE Xplore search result pages.

The script:

1. Opens a manually configured search URL in Chrome.
2. Locates article links using CSS selectors.
3. Collects URLs from the current results page.
4. Attempts to navigate to the next results page.
5. Saves the collected URLs to an Excel file.

The output file used in the example script is:

`scraped_links_Power_Engineering.xlsx`

### Libraries and Tools

- Python
- Selenium
- pandas
- Chrome WebDriver
- webdriver-manager

## 2. Article Metadata and Abstract Extraction

After collecting article URLs, a second Python script was developed to extract information from individual article pages.

### Extracted Fields

The script attempts to collect the following information:

- **Link:** Article URL
- **Title:** Article title
- **Authors:** Names of listed authors
- **Journal Name:** Journal name
- **Publication Date:** Publication date displayed on the article page
- **Abstract:** Scientific abstract

### Extraction Workflow

1. Read article URLs from an Excel file using `openpyxl`.
2. Open each URL with Selenium WebDriver.
3. Wait for the article title element to become visible.
4. Parse the page HTML using BeautifulSoup.
5. Extract the available metadata and abstract.
6. Save the extracted records to a structured Excel workbook.

The output workbook contains columns for the article link, title, journal name, publication date, abstract, and up to ten author fields.

### Output

The example script saves the extracted records to:

`out_scraped_links_Power_Engineering.xlsx`

### Libraries and Tools

- Python
- Selenium
- BeautifulSoup
- openpyxl
- Chrome WebDriver
- webdriver-manager

The extraction process depends on the HTML structure and selectors used in the script. Missing fields may be replaced with fallback values, such as `Abstract not found`.

## 3. AI-Generated Abstract Construction

### Objective

A separate Python script was developed to generate synthetic academic abstracts from article titles using the OpenAI API.

Unlike the paraphrasing stage, this process does not provide the original abstract to the model. Instead, the model receives the article title and generates a new abstract based on that title.

### Input Data

The input Excel file in the provided example is:

`out_scraped_links_Psychology.xlsx`

The script requires a column named `Title`.

### Model and Configuration

- **Model:** `gpt-3.5-turbo`
- **Temperature:** 0.8
- **Request timeout:** 30 seconds
- **Processing batch size:** 10 records
- **Delay between requests:** 2 seconds

The batch size controls progress reporting and processing organization. Requests are sent individually rather than as a single batch API request.

### Prompt Design

The prompt requests an academic abstract of 150–200 words and instructs the model to:

1. Use a formal academic tone.
2. Introduce the broader research context.
3. Explain the research problem, significance, and motivation.
4. Summarize the methodology.
5. Present findings and contributions.
6. Vary vocabulary and sentence structure.
7. Maintain a coherent flow from the research problem to the contribution.
8. Return only the abstract without additional commentary.

### Output

The generated abstract is stored in a new column named `Abstract-gpt3-5`, while the original article metadata remains in the DataFrame.

The output file specified in the example script is:

`gpt_new_perampt_out_scraped_links_Psychology.xlsx`

### Methodological Considerations

These records represent synthetic abstracts generated from research titles. Because the model does not receive the original abstract or verified study findings, its descriptions of methods, results, and contributions may be inaccurate or fabricated.

The generated records should therefore be interpreted as title-conditioned synthetic text, rather than verified summaries of the corresponding published studies.

## 4. AI-Based Abstract Paraphrasing

### Objective

Another Python script was developed to paraphrase existing scientific abstracts using the OpenAI API and pandas.

Unlike synthetic abstract generation, this process receives the original abstract as input and attempts to preserve its meaning while changing its wording and sentence structure.

### Input Data

The input Excel file in the provided example is:

`gpt_out_scraped_links_Sociology.xlsx`

The script requires a column named `Abstract`.

### Prompt Design

The paraphrasing prompt instructs the model to:

- Preserve the original meaning and key points.
- Rephrase sentences using different vocabulary and structures.
- Maintain a clear, formal, scholarly tone.
- Produce fluent academic text.

### Model and Configuration

- **Model:** `gpt-3.5-turbo`
- **Temperature:** 0.7
- **Request timeout:** 30 seconds
- **Processing batch size:** 10 records
- **Delay between requests:** 2 seconds

As in the synthetic generation stage, each abstract is submitted as an individual API request.

### Output

The paraphrased text is stored in a new column named `Abstract-Paraphrase`, alongside the original article metadata.

The output file specified in the example script is:

`paraph_2_gpt_out_scraped_links_Sociology.xlsx`

### Methodological Considerations

The paraphrased abstracts are derived from existing abstracts rather than generated independently from titles. They therefore represent a different text-generation process from the GPT-3.5 synthetic abstracts.

Paraphrasing may preserve substantial semantic and lexical information from the original text. This relationship should be considered when constructing data splits and evaluating classification performance.

## 5. Dataset Classes

The research design distinguishes between three text categories:

| Class | Description | Text source |
|---|---|---|
| `Human` | Original scientific abstracts treated as presumed human-written | Collected article abstracts |
| `GPT-3.5` | Synthetic abstracts generated from article titles | GPT-3.5 API |
| `Paraphrase` | Rewritten versions of original abstracts | GPT-3.5 API |

These categories correspond to different text-generation origins. The final class counts, labeling procedure, duplicate handling, and dataset balancing strategy will be documented after verification of the dataset preparation code.

The `Human` label reflects the study's working assumption about the collected historical abstracts; it does not establish that every abstract was written without any AI assistance.

## Stylometric Feature Extraction and Exploratory Data Analysis

After collecting and preparing the dataset, linguistic and readability-related features were extracted from human-written, GPT-3.5-generated, and paraphrased scientific abstracts.

The extracted features included word and sentence counts, average word length, syllable statistics, Type-Token Ratio (TTR), punctuation counts, and five readability indices: Flesch Reading Ease, Flesch–Kincaid Grade Level, SMOG, Coleman–Liau Index, and Automated Readability Index (ARI).

Exploratory data analysis was then performed to compare feature distributions across the three text categories. This stage included descriptive statistics, boxplots, Kruskal–Wallis tests, correlation analysis, word frequency comparisons, and word cloud visualization.

The processed dataset, statistical summaries, and visualizations were saved for further analysis.
